Data format

Version 0: a first design based on the balance-sheet and exposure data used in published interbank contagion studies. It is meant to be corrected with feedback from the people who will use it.

Institutions file (required)

A CSV with a header row and one row per institution. All amounts are in millions of one currency. Column names ignore case, spaces, dashes and underscores.

ColumnMeaning
institutionA unique name. Also accepted: name, bank.
cash_and_reservesLiquid assets: cash and central-bank reserves. Also: cash, reserves.
loans_and_securitiesAll other assets outside the banking system. Also: loans, external_assets.
interbank_assetsTotal lent to other institutions in the file. Optional if you supply exposures.
deposits_and_other_liabilitiesLiabilities to customers and anyone outside the file. Also: deposits, other_liabilities.
interbank_liabilitiesTotal borrowed from other institutions in the file. Optional if you supply exposures.
equityCapital. Also: capital. If blank or absent, it is computed as assets minus liabilities.

Exposures file (optional)

One row per bilateral loan: the lender, the borrower and the amount. Also accepted: creditor, debtor, exposure.

lender,borrower,amount
Alder Bank,Birch Bank,4200
Birch Bank,Cedar Bank,1800

Rows for the same pair are added together. If you also give interbank_assets and interbank_liabilities, they must agree with the exposures to within 0.5%.

Without an exposures file

Bilateral exposures are often confidential. If you leave the exposures file out but give each institution's interbank_assets and interbank_liabilities, the model estimates who lent to whom by proportional allocation: each institution's lending is spread across the others in proportion to their borrowing. This is the standard fallback in the literature, and it tends to understate how concentrated real exposures are, so treat contagion results as indicative. The window says whenever it has done this.

Files saved from Excel

The files are read as text (CSV), so save from your spreadsheet with Save as → CSV. The following are handled automatically, and the window tells you when it relied on one of them:

  • Separators: commas, semicolons or tabs (Excel in many European locales writes semicolons), and a leading sep=; line.
  • Decimal commas: if the numbers look like 1.234,5 or 12,5 and nothing looks like 1,234.5, commas are read as decimals. Thousands separators, spaces and currency symbols (€ $ £ ¥, or EUR, USD, GBP) are ignored, and (1,234) is read as negative, which is then reported because balances cannot be negative.
  • Unit notes in headings: cash_and_reserves (EUR m) is the same column as cash_and_reserves.
  • Encodings: UTF-8, UTF-16 with a byte-order mark, and Windows-1252 (Excel's "CSV" on Windows) are read; a file that is not UTF-8 is flagged so you can check that accented names look right.

How large a network can be

Between 2 and 40 institutions. With a supplied exposures file, each pair that has a loan gets a set of links, so the model has roughly 7 relationships per loan plus about 7 per institution; on a typical laptop, 40 institutions and a few hundred exposures import in under a second and run for 60 days in about a second. When exposures are estimated, each institution keeps its 10 largest counterparties in each direction to keep the network readable. Models with more than 150 relationships open in the Konjugate canvas with relationship labels hidden; the Edges button in the Details control brings them back.
